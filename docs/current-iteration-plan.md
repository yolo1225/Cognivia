# 当前迭代计划

## 下一迭代：领域知识自动导入与知识图谱构建

按照 `docs/领域知识库自动导入与知识图谱构建实施方案.md` 分 P0-P5 交付：先冻结金标准与回归基线，再实现稳定 Chunk、多来源关联、结构化确定性导入、模型增强、可恢复编排和事务发布，最后完成知识管理前端收敛与第二领域验收。当前活动合同为 V9；学习主图拓扑不在本迭代继续修改范围内。

### 当前增量：题库密度与个性化动态组卷（2026-08-26）

- 正式题库不再按每知识点六个固定题槽导入；每个已发布知识点保留至少一道主归因题，额外题优先分配给图谱中心和核心知识点，领域总量仍保持不少于 60。
- 运行时测验只从 `active + certified` 正式题库确定性选择；2–6 个节点成员对应期望 4–8 题，3–5 道匹配题可正常发布，少于 3 道在创建任务前返回具体题库密度提示。
- 合同 V9 将 `graded_quiz.questions` 调整为 3–8，移除单次测验必须三层齐全的校验；题目真实 `difficulty` 保持认证值，`quiz_level` 只描述教学用途。
- Readiness 同时检查认证总量、每知识点主归因、题型、教学层级、1–5 难度分布和来源/内容哈希；单元级预检另报告目标难度、重点知识点与题型风险。

### 当前增量：正式题库精确证据认证（2026-08-26）

- 题目改为使用 Candidate 索引同版本 Chunker 的最终 Chunk 生成：基础题绑定主知识点的 1 个 Chunk，提升题绑定 1-2 个 Chunk，挑战题绑定 1-3 个 Chunk且只允许跨有正式知识关系的关联知识点；每条原文引文显式绑定一个 Chunk，并保存 locator、来源内容哈希和 Chunker 版本。
- 导入在题目生成后增加独立 `question_certification` 阶段：先做确定性证据/结构校验，再由一个独立认证模型执行题库准入复核；失败字段最多触发两轮定向补题。比赛要求的双模型交叉审核继续只由运行时 Review Agent 对个性化学习包执行，避免导入阶段重复建设第二套审核系统。
- 正式题目新增 `pending / certified / rejected / stale` 认证生命周期；诊断、节点测验和验证只允许使用 `active + certified`，认证不替代运行时双模型包级审核。
- Readiness、知识题库 API 和知识管理页面统一展示并只统计有效认证题；认证总量、逐点覆盖或题型/三层级分布不足时导入进入 `needs_attention`，不发布不完整题库。

## V6质量稳定性迭代（2026-08-18）

## 当前演示路线

知识管理的新领域创建采用文档驱动流程：管理员只填写领域代码和名称，上传文档后由系统根据
知识分类与标签建议学习方向，并与知识、关系、题目和 Candidate 索引在一次确认发布中共同生效。
学习方向不再是创建领域或上传文档的人工前置条件。

```text
学习背景与方向采集 -> 首次诊断测评 -> 学习画像与路线 -> 资源生成 -> 自动审核/修订 -> 资源质量指标
-> 学习反馈 -> 导学与画像更新 -> 学习报告 -> 知识管理
```

首次学习者在学习中心完成“三步建档”：学习背景与方向、10 题首次诊断、初始画像与路线。只有画像谱系已经完成首次诊断且保存了背景快照时，才解锁资源、报告、任务记录和学习包生成；默认种子画像不视为完成，反馈更新后的新版本沿用该快照。

资源页仅展示任务与资源的三项质量指标，不展示 Agent 节点图或人工复核入口。后端仍保留结构化 Agent Run 记录用于可追溯性和离线评测。

知识条目或关联知识更新后，历史学习包保持不变。当前学习包若受到影响，资源页继续展示完整三类资源并提示知识已更新；向量索引就绪后由用户决定是否局部刷新。每次刷新作为新的学习历程事件，学习历程明确区分本次生成资源与继承资源。
