# 当前迭代计划

> 最近同步：2026-08-29
> 活动契约：`agent-contract-v10`

## 当前实现基线

项目已形成可演示的生产学习闭环：

```text
建档与诊断 -> 学情画像 -> 学习路径 -> Candidate RAG
-> 三类资源生成 -> 双模型审核 -> 自动定向修订
-> 原子发布 -> 导学、错题与反馈更新
```

- 唯一主图由 `build_learning_graph()` 构建，最多两轮自动修订。
- 检索只使用已发布领域的 active Candidate index，Top-K 上限为 18。
- 证据能力用于检索排序、诊断和知识治理，不是生成硬门槛。
- `practice_guide` 优先承担具有操作证据的知识点；纯概念证据时仍生成可追溯的分析、设计、比较、评审或记录任务，只有目标知识点缺少有效检索证据才阻断生成。
- 生成保留 Schema、来源白名单、认证题库和可审核声明硬约束；知识点或能力缺口只记录 warning。
- 审核对证据不足、明确矛盾、覆盖不足或双模型分歧执行补检索；空补检索继续完成审核。
- 发布只依据幻觉率 `<5%`、难度匹配 `>=85%`、核心覆盖 `>=90%` 和基本结构有效性。
- 三类资源必须完整通过后原子发布，不发布不完整学习包。
- 活动正式题库已收敛为互斥的 `diagnosis`、`graded_quiz`、`mastery_validation` 三类用途；当前
  `ai_app_dev` 为 65 道诊断题、150 道分阶测验题和 100 道掌握检查题。
- 首次诊断和分阶测验错题直接重做原题；修正结果参与画像更新，但与独立掌握检查证据分离。
- 路线推进要求当前节点相关错题全部解决，同时满足分阶测验和独立掌握证据门禁。
- 分阶测验选题、预检、生成和审核共用目标难度 `±2` 标准；不足 3 题时仅按难度距离兜底补足。
  修订保留已通过题目并只替换未通过位置，不放宽认证、用途、范围、来源或结构约束。
- 题目由 MySQL 直接筛选，题目用途或库存变化不触发 Candidate 重建；知识 Chunk 变化才重嵌入。
- 正式题库认证统一使用 `question-cert-v2`：题干、唯一正确答案与解析必须由绑定来源支持；明确错误的跨知识点干扰项允许存在，过于无关仅记录质量警告。认证服务异常、内容不合格和来源待确认分开处理。
- `question-cert-v1` 仅作为迁移期兼容版本；运行 `python -m app.scripts.recertify_question_bank_v2 --domain-code <code>` 完成存量重认证后移除兼容。

## 当前交付顺序

### P0：生成链路稳定性与可复现验收

1. 重放历史失败形态，验证概念证据可生成实训学习活动并进入审核。
2. 验证补检索为空仍能形成审核报告和最终指标决策。
3. 验证并行资源只重试失败类型，持续失败时保留具体错误记录且整包不发布。
4. 固化生成、检索、审核、Orchestrator 和图集成测试。
5. 使用隔离环境统计历史任务重放成功率，不回写生产历史记录。

### P1：领域知识导入与图谱质量

1. 保持文档批次导入、候选校验、图谱预览、Candidate 索引、冒烟与确认发布链路稳定。文档导入只发布知识、关系和 Candidate 索引，不再调用模型生成正式题目。
2. 正式题库通过题库管理中的 XLSX 缺口模板独立导入。模板按已发布知识点和 `diagnosis`、`graded_quiz`、`mastery_validation` 的缺口生成，上传后必须完成来源绑定和认证才可原子发布；知识已发布但题库未补齐时领域保持 `preparing`。
3. 提高真实知识 Chunk 中概念、操作、结果、代码和排错证据的可检索性。
4. 保持关系无环、来源可追溯、题目绑定 Chunk 和认证生命周期门禁；增量导入按完整领域目录补充新学习方向，手工教学关系以 `curriculum_rule` 保存，并可在不重传文档的情况下重新校验图谱。
5. 保持新领域每知识点至少 1 道诊断题、3 道分阶测验题和 2 道掌握检查题，且活动题唯一用途。
6. 完成第二领域小规模导入与同一学习闭环复用证明。
7. 增量维护使用 `domain_change_sets`：活动领域在准备资料、索引和题库时保持可用；变更集中的知识、关系、Candidate 索引和认证题库在完成缺口后一次启用。普通上传只追加或更新稳定 `knowledge_id`，不根据“新文件缺少某节”自动删除知识；文档替换需显式 `replace` 模式和确认。
8. 题库 XLSX 模板同时校验知识目录指纹和题库缺口指纹。相同文件可幂等重试；同一旧模板在其他批次发布后失效。模板可按知识点范围分批下载，正式启用仍以完整缺口为门槛。

### P2：比赛评测与演示封装

1. 固定不少于 50 个评测案例和至少 3 类差异化画像。
2. 运行 smoke、regression、formal 和稳定性评测，保存模型、知识版本与索引指纹。
3. 固定演示脚本，覆盖画像差异、三类资源、审核补检索、局部修订、反馈更新和知识发布。
4. 输出材料中的指标只引用当前可复现报告，不沿用旧版本成绩说明。

## 本迭代不做

- 不修改 V10 字段、枚举、State 或顶层图。
- 不引入 Neo4j、WebSocket、通用分布式队列或企业级权限系统。
- 不建设在线人工审核工作台或部分资源发布机制。
- 不新增前端能力完整率发布门槛。
- 不恢复生成期内容策略修复、覆盖修复或证据能力硬失败逻辑。

## 完成标准

- 活动文档、Prompt 和代码只声明 V10 为当前契约。
- 单元与图集成回归通过，Prompt 注册中没有已删除修复路径。
- 真实评测满足官方三项指标，执行成功率与质量指标分别报告。
- 文档入口、部署命令和 API 说明可用于从零完成比赛演示。
