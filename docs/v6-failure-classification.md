# V6 生成与审核故障分类

复核日期：2026-08-19。

## 判定原则

每个失败先归入以下一种主因，禁止把所有问题折叠为“模型生成失败”：

| 主因 | 判定条件 | 处理方式 |
|---|---|---|
| 程序缺陷 | 正确案例和充分知识已存在，但目标分配、检索、合并、校验、持久化或运行隔离行为错误 | 修代码并增加回归测试 |
| 知识数据缺口 | 案例目标有效，但知识源缺少支撑所需事实、步骤、命令、代码、预期结果或错误处理证据 | 补知识、标记重嵌入、重建索引并复测 |
| 案例缺陷 | 目标不存在、预期互相矛盾、资源类型与目标能力天然不兼容，或案例结构违反版本化评测合同 | 修案例并更新案例集哈希；不得改审核规则迁就 |
| 外部模型/服务故障 | 已配置服务超时、限流、不可用或返回无法解析结果，且本地合同与输入有效 | 按1/3/5秒重试，耗尽后记录精确终态 |
| 运维/环境故障 | 会话过期、容器中断、进程遗留、索引版本不一致或运行配置变化 | 检查点恢复、配置绑定、清理孤立运行后重跑 |

`evidence_insufficient` 是审核结论，不自动等于案例缺陷。只有确认案例要求本身不成立时才改案例；否则应定位检索程序或知识数据。

## 规则强度结论

旧实现确实存在“用错层级”导致的过严：每个资源重复承担包级覆盖线、刷新后剩余资源被塞入全部目标。这两项已修复。

以下规则不应放宽：明确矛盾、证据不足、仲裁未解决都阻止受影响资源发布；差异超过10分或通过结论冲突必须仲裁；两次局部修订仍失败才终止。放宽这些规则会提高偶然成功率，但会直接损害反幻觉指标和比赛可信度。

正确的稳定性策略是：先预检证据能力，再确定性分配目标，检索所有非支持声明，局部补丁修订，并对可恢复故障重试和恢复。规则保持严格，失败原因必须精确且可操作。

事实审核的输入边界也必须准确：学习者要完成的阅读、记录、整理、标注或提交动作不是关于外部世界真假的事实声明，不应进入幻觉分母；动作中嵌入的具体技术行为、版本、参数、固定结果或错误语义仍必须进入双模型审核。这是修正审核对象，不是放宽审核结论。
