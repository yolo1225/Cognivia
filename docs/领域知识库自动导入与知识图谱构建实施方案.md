# 领域知识库自动导入与知识图谱构建实施说明

> 最近同步：2026-08-29
> 适用契约：`agent-contract-v10`
> 本文只描述当前实现和明确的下一步，不定义学习主图的新契约。

## 1. 目标与边界

知识导入链把管理员上传的领域材料转换为可发布、可检索、可追溯的知识包：

```text
上传文档 -> 解析与稳定 Chunk -> 知识候选
-> 关系候选 -> 确定性校验和独立复核
-> 图谱预览 -> Candidate 索引 -> 检索冒烟 -> 确认发布
```

导入服务独立于学习 Agent 主图，不修改 V10 State 或节点拓扑。第一版使用 MySQL 保存知识关系，
ChromaDB 保存向量索引，不引入 Neo4j。

## 2. 当前数据产物

- 来源文档及内容校验值；
- 稳定知识 ID、名称、分类、难度和正文；
- 带来源定位、标题路径和内容校验值的 Candidate Chunk；
- `prerequisite/dependent/related/next_step` 等知识关系；
- 独立 XLSX 题库导入运行、逐行来源候选、认证状态与错误字段；
- staging/active Candidate manifest、embedding 模型和索引版本；
- 导入批次、阶段、错误摘要、图质量和 readiness 结果。

日志不记录完整文档、题目或资源正文，只记录 ID、状态、计数、耗时和脱敏错误。

## 3. Chunk 与证据能力

Chunk 必须保持标题路径、来源定位和稳定校验值。结构化材料按知识点和章节切分；通用 Markdown、
PDF、TXT 等文档先解析段落，再形成候选，不把整份文档作为单一知识点。

证据能力使用领域中立的规范值，例如：

```text
concept, example, operation, command, code_example,
expected_result, error_handling, version_boundary
```

能力标签用于检索排序、知识缺口解释、readiness、离线评测和知识治理，不用于阻止生成。不得为了
满足标签分布把理论材料伪装成操作、固定结果或代码证据。

## 4. 知识关系

关系候选来自显式文档依赖、课程规则和局部模型判断。模型只处理带精确来源的局部候选，输出后
执行端点存在性、去重、自环、方向、证据和有向环校验。

- `prerequisite` 决定必要前置；
- `dependent` 是前置关系的反向查询视图；
- `next_step` 表达教学推荐顺序；
- `related` 用于检索扩展和知识浏览，不替代前置关系。

关系数量不是发布目标，可信方向和路径可用性优先于边数量。

## 5. 正式题库

文档导入不生成正式题目。题目由种子数据或题库管理下载的 XLSX 缺口模板独立导入；模板按
已发布知识点、用途和槽位预填，出题人员只填写题型、难度、题干、选项、答案、解析和评分点。
每道题保存稳定 external ID、主知识点、题型、难度、答案、解析、来源引用和内容哈希。

题目先通过结构、答案、选项、来源和归属的确定性校验，再由独立认证通道检查事实支持度。
生命周期为：

```text
pending -> certified | rejected
certified -> stale
```

活动题必须唯一归入 `diagnosis`、`graded_quiz` 或 `mastery_validation`。新领域每个已发布知识点
至少提供 1 道诊断题、3 道分阶测验题和 2 道掌握检查题，其中掌握检查包含基础检查与迁移检查。
所有入口只使用 `active + certified` 题目；单次分阶测验最低 3 题，题库不足时明确失败，不允许
模型临时生成题目冒充认证题。空用途、多用途、未知用途在导入发布前拒绝。来源自动匹配不足时
由管理员选择 Candidate Chunk 并圈选精确原文；不回退到模型补全来源。一份 XLSX 必须全行认证
通过才能原子发布，知识已发布但存在题库缺口时领域保持 `preparing`。

错题巩固不占用题目用途。诊断和分阶测验错误保存原题 ID，巩固时直接重做原题；掌握检查从
`mastery_validation` 池选择未见题，错误不进入错题本。

## 6. Candidate 索引与发布

索引构建保存领域、数据版本、embedding 模型、维度、距离度量、Chunker 版本、集合名称和 Chunk
数量。发布前必须确认 manifest 与集合存在且元数据一致、知识和来源校验通过、图谱不存在阻断性
结构问题、正式题库满足 readiness，并且显式知识点和语义检索冒烟通过。

构建始终先写 staging collection。只有确认发布成功才切换 active manifest；失败批次不影响现有
学习者检索。真实 embedding 或模型调用必须在用户授权后执行。

## 7. 与学习闭环的关系

学习主图只读取已发布领域：

```text
active Candidate index -> Knowledge Retrieval Agent
MySQL active + certified diagnosis -> 首次诊断
MySQL active + certified graded_quiz -> 分阶测验
MySQL active + certified mastery_validation -> 掌握检查
knowledge_relations -> 路径、关联召回和影响分析
```

题目不作为向量召回对象；检索 Agent 在知识范围确定后直接查询 MySQL 题库。因此仅调整题目用途、
认证状态或库存不需要重建 Candidate 索引，只有知识正文、来源 Chunk 或 embedding 配置变化才需要。

知识更新后将受影响条目标记为待重嵌入，通过关系定位相关路径，并在现有字段可用时将相关资源
标记为 `review_stale`。新索引发布后，后续生成任务自然使用新证据；历史资源和历史评测不回写。

## 8. 当前 API 与界面

管理员通过 `/api/v1/knowledge/documents`、`/knowledge/imports`、`/knowledge/items`、
`/knowledge/relations`、`/knowledge/questions`、`/question-imports` 和 `/domain-change-sets` 完成上传、
候选复核、图谱预览、索引、题库认证和一次启用。准确字段以 OpenAPI 与 `docs/api-v1.md` 为准。

知识管理页面必须展示加载、空、失败和阶段进度状态，并区分 staged 与 active 数据。一次“确认并
发布”是管理员对整批候选的最终确认，不建设企业级多级审批流。

## 9. 下一步与验收

下一步聚焦真实操作、结果、代码和排错 Chunk 的召回质量，固化导入中断恢复和 staging 事务发布
测试，并完成第二领域小规模导入。

验收覆盖重复导入幂等、来源定位、关系无环、题目认证、索引元数据一致、冒烟检索、失败不污染
active 数据，以及 `ai_app_dev` 诊断、画像、检索、生成、审核和反馈闭环无回归。
